# 真实体验关（Plus 新增）：复杂项目必须真跑一遍，按体验标准打分

**为什么要有这一关**：9 维度评分和 test-prompts 只看「说明书写得对不对」，测不出慢、点了没反应、图看不全、文件夹一堆垃圾这种体验问题。用户实操一遍才发现，等于第一版没做好。这一关分两段：**做之前先写体验剧本（预防），做完真跑一遍打分（检查）**。

## 哪些项目要过
满足任意一条就算复杂项目，必须过；都不满足就跳过，报告里写一句「简单 skill，跳过体验关」：
- 会打开网页 / 页面让用户点
- 用户要确认两次以上
- 一次完整使用要超过 3 分钟
- 会往用户的文件夹里写文件

## 第一段：体验剧本（Phase 0.6，在设计 test-prompts 之后）
在被测仓库里建 `tests/ux/journey.json`（已经有就读它，不重写）。用大白话想清楚：用户是谁、输入什么、每一步看到什么、点什么、等多久、最后拿到什么。

```json
{
  "project": "仓库名",
  "user": "什么都不懂的小白创作者",
  "input": "tests/ux/fixture/ 里放什么（越小越好：30 秒视频、3 句话的文档）",
  "request": "用户会怎么开口，比如：帮我给这个文件夹里的口播视频配 B-roll",
  "steps": [
    {"id": "first_reply", "name": "AI 第一句回应", "budget_s": 10},
    {"id": "page_open", "name": "页面打开", "budget_s": 120},
    {"id": "samples_ready", "name": "风格样图出齐", "from": "mode_chosen", "budget_s": 120},
    {"id": "done", "name": "成片放进文件夹", "from": "all_approved", "budget_s": 300}
  ],
  "answers": {"AI 问到选哪个风格": "就第一个", "AI 问要不要保存风格": "保存"},
  "page_script": "tests/ux/page.json",
  "limits": {"first_feedback_s": 10, "silent_wait_s": 30, "click_response_s": 5, "user_clicks": 20, "user_messages": 3, "asks": 2},
  "deliver": {"allow": ["口播*.mp4", "B-roll成片/*.mp4"], "must": ["B-roll成片/*.mp4"]},
  "total_budget_s": 900
}
```

**默认体验标准**（开发者没说就用这套，写进 limits）：
| 标准 | 默认 | 为什么 |
|---|---|---|
| 开工多久有第一句反馈 | ≤ 10 秒 | 用户发完消息没动静，会以为坏了 |
| 最长干等（看不到进度） | ≤ 30 秒 | 超过就要显示「正在做什么、大概还要多久」 |
| 页面点了多久有反应 | ≤ 5 秒 | 点了没反应 = 坏了；页面上的按钮必须能直接叫醒 AI，不能要用户回对话发消息 |
| 用户发消息 | ≤ 3 条（第一条需求不算） | 能点的就不让打字 |
| AI 停下来问 | ≤ 2 次 | 能自己判断的不问；要选的一次给全 |
| 结果一次看完 | 全部 ✅ | 图多就自适应缩小、点开放大，不要「换一批」、不要一张一张发 |
| 文件夹 | 只有用户要的 | 中间文件放隐藏文件夹 |
| 出错 | 人话 + 下一步 | 不贴报错原文让用户猜 |

**🔴 CHECKPOINT**：把剧本用大白话给开发者看（每一步：用户看到什么、点什么、最多等多久），开发者点头或改两句再往下。之后优化和测试都照这个来。

## 第二段：真跑（Phase 1 摸底一次，Phase 3.5 验收一次）
1. **准备**：把 `tests/ux/fixture/` 复制到临时文件夹（真跑会往里写东西，不能弄脏仓库）。新建流水 `ux-流水.jsonl`，先记 `ux_log.py <流水> start`。
2. **派一个执行者**（子任务 / subagent，用平时干活的模型）真的按 skill 把 `request` 做完，要求它：
   - 每对用户说一句话就 `ux_log.py <流水> say "原话"`；走到剧本里的步骤就 `ux_log.py <流水> step <id>`；停下来问用户就 `ux_log.py <流水> ask "问题"`，再从 `answers` 里找答案当用户回复（`ux_log.py <流水> user_msg "答案"`），找不到就选小白最可能选的那个；全部做完 `ux_log.py <流水> end`。
   - skill 要打开页面时：**不要自己点**，在后台跑 `python3 <本skill>/scripts/ux_page.py <页面地址> --script <page_script> --journal <流水> --shots <截图文件夹>`，它像真人一样等、点、截图、记反应时间；执行者照常干自己的活（页面上点了有没有叫醒它，正是要测的）。
3. **打分**：`python3 <本skill>/scripts/ux_report.py tests/ux/journey.json <流水> --folder <临时文件夹> [--prev tests/ux/上次成绩.json] --out <结果文件夹>/体验成绩单`，最后一行 `STATUS=PASS / FAIL`。
4. **小白评审**（用最便宜的模型，比如 Claude 里 `model: haiku`）：只给它截图文件夹和成绩单，问「你是第一次用的小白，哪里看不懂、哪里不知道点什么、哪里等太久」，最多列 5 条。
5. **存档**：成绩单 `.json` 复制成 `tests/ux/上次成绩.json`，下次对比；截图不进仓库。

## 怎么用结果
- 成绩单有 ❌ → Phase 2 第一轮定为 **P0「体验修复」**，和平台适配 P0 一起修。修的是 skill 本身（流程、页面、脚本），不是改剧本放水。改剧本必须开发者同意。
- 小白评审的意见当候选改进，按 9 维度一起排优先级。
- Phase 3.5 再真跑一次：**不能有 ❌，也不能比上次慢 / 多点 / 多问**；变差就撤回那次改动。

## 省钱规则（不然复杂项目 token 烧到飞起）
- **能用脚本就不用 AI**：点页面、计时、数点击、看文件夹都由 `ux_page.py` / `ux_report.py` 做，不花 token。
- **测试材料要小**：30 秒视频、3 处标黄、3 句话的文档。体验问题在小材料上一样会暴露。
- **假用户不用 AI**：回答写死在 `answers`，页面操作写死在 `page_script`。小白评审用最便宜的模型，只看截图。
- **只真跑两次**：Phase 1 摸底、Phase 3.5 验收。中间每轮只跑静态检查和 test-prompts。
- **只重跑改过的那段**：剧本步骤可以从中间开始（执行者直接用 fixture 里存好的中间结果，比如已经听写好的字幕），只改了选风格页面就从选风格那一步跑。
- **设上限**：一次真跑超过 `total_budget_s` 的 2 倍就停，成绩单写「超时没跑完」，当 ❌ 处理。
- **Codex 只在发布前跑前两步**：确认能装、能开工、能打开页面就行，不跑全程。

## 老实写
- 真跑只证明「在这台电脑上、用这份小材料」体验达标。报告里写清：在哪个 AI 里真跑的，哪些 AI 没真跑。
- 测不到的（比如真人对颜色的喜好），写进「还要你自己看一眼」，不要算成通过。
